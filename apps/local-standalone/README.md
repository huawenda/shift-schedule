# 倒班表 · 本地版（standalone）

一个**可分发**的离线排班工具：不联网、不登录、没有账号和后端，把整包拷到任何
Windows 电脑上就能用，数据只存在那台机器的浏览器里。

它不绑定任何具体的人或班组。**班序是 24 天一轮的循环：13 条常用班序（4F–4X）内置只读，
不够用时可以照同样的 24 格自己再建一条；姓名、人数、谁挂哪条班序由使用者自己填。**
所以同一份程序可以给不同的小组各自用。

> 界面按 1440×900 办公电脑屏设计，窗口宽度建议不低于 1280。
> 全站强制浅色（`color-scheme: light`，无暗色分支）——廉价办公屏上深色观感差。

## 1. 快速开始

### 双击启动（不想开终端时）

双击本目录的 **`dev.bat`**：起开发服务器 + 自动打开默认浏览器，关掉窗口即停止。
脚本会先 `cd` 到自己所在目录，所以从资源管理器任意位置双击都能用。

带任何参数运行时**不**自动开浏览器，方便调试：`dev.bat --port 7000`。

要起**桌面壳**（Tauri）则双击 **`tauri-dev.bat`**：自动起 6182 的 dev server + 编译 Rust + 开原生窗口。
它和 `dev.bat` 是两条独立的线，不要同时用同一个端口；两个可以并存（6180 与 6182 错开）。

### 命令行

```bash
pnpm --filter shift-schedule-local dev    # http://127.0.0.1:6180/
pnpm dev                                  # 在本目录下同理
pnpm dev -- --open                        # 顺便打开浏览器
pnpm dev -- --port 0                      # 让系统挑一个空闲端口
pnpm dev -- --lan                         # 绑 0.0.0.0，同局域网设备可访问
pnpm dev -- --strict-port                 # 端口被占用时直接报错，不自动顺延
```

端口 6180 被占（多半是上一个 dev server 没退）时，脚本会明确提示并自动顺延，
打印的地址取自实际监听结果，不会印错。

### 用现成产物（不需要 Node）

`pnpm build` 之后把 `dist/` 整个文件夹拷走，双击里面的 `index.html` 即可（见 §8）。

## 2. 这个工具做什么 / 不做什么

| 做 | 不做（本版明确不做） |
|---|---|
| 自定义成员（姓名、人数、挂哪条班序） | 统计页、薪资计算 |
| 自建 24 格班序（最多 10 条，可改可删） | 改周期长度、加新班次种类 |
| 点格子改某天某人的班次，可恢复默认 | 事假半天/一天（按小时计） |
| 个人日历里记加班小时、标法定节假日 | 加班费/倍率（留给统计页） |
| 导出/导入 JSON 备份（当前格式，不兼容旧版） | 云同步、多设备、多套排班表 |
| 完全离线可用（`file://` 双击即开） | 手机端布局（只做大屏 PC） |

左侧导航里的「统计」是**禁用状态**，标着「下一版」。这是刻意留的接口位，
不是没做完的残骸 —— 加班与法定数据已经在录，统计页接上就能算。

## 3. 核心模型

理解这四条就理解了这个项目，其余都是它们的视图。

### 3.1 班序内置 13 条，人自由

- 内置 **13 条班序**：`4F` `4G` `4H` `4I` `4J` `4K` `4R` `4S` `4T` `4U` `4V` `4W` `4X`，**只读**
- 每条 **24 天**一个循环，锚点日 **2026-06-07**，向前向后都能推算（不需要预生成日期区间）
- 不够用时可以在设置里**自建班序**：同样 24 格，每格从固定 6 种班次里选，名字随便起，
  最多 **10 条**（`MAX_CUSTOM_PATTERNS`），**可改名、可改序列、可删除**
- **周期长度不可改**：`PATTERN_CYCLE_LENGTH` 是全局常量 24，自建班序也照此，推算算法只有一套
- 成员 = `{ id, name, patternId }`，**同一班序可以挂多人**——这些人每天的班次完全一致
- 人数上限 200（`MAX_MEMBERS`），实际使用远到不了

改一条自建班序的 24 格会**全量生效**（包括已经过去的月份）——班序是无始无终的循环，
没有「从哪天起生效」这回事。删除自建班序会**连带删除挂在上面的成员及其改班记录**，
所以要求输入班序名字才能确认。

### 3.2 六种班次，语义写死

| 班次 | 矩阵单字 | 时段 | 算出勤 |
|---|---|---|---|
| 白班 | 白 | 08:00 起 12h | 是 |
| 夜班 | 夜 | 20:00 起 12h | 是 |
| 休息 | 休 | — | 否 |
| 白特 | 特 | 08:00 起 12h | 是 |
| 夜特 | 特 | 20:00 起 12h | 是 |
| 事假 | 假 | — | 否 |

白特/夜特在矩阵里都是「特」（22–24px 列宽放不下两个字），靠颜色和图例区分。
**颜色不单独表意**：矩阵下方永远显示六色图例，弹层里显示全称。

### 3.3 加班与法定只挂在有工时的班次上

- **能记加班的四种**：白班 / 夜班 / 白特 / 夜特。休息与事假不产生加班，选到它们时两段整体禁用并清零。
- **输入精度**：0.5 小时步长，向下取整（`2.7 → 2.5`），上限 24 小时。
- **预设档位**（与 Web、小程序口径一致）：
  - 白/夜 普通 → `2h / 3h / 3.5h`
  - 白特/夜特、或白/夜标了法定 → `10h / 11h / 11.5h`
- **加班只在「个人日历」里录**。全员矩阵的弹层保持只改班次 —— 矩阵是排班视图，
  加班是逐人逐天的明细，混在一起容易误点。
- ⚠️ 矩阵里把某天改成休息/事假时，**该天已有的加班与法定会被一并清掉**，
  弹层会提前提示「这天有 +3h 加班记录，改为休息会一并清除」。

### 3.4 结算月不是自然月

每个「月」是**上月 20 日 ~ 本月 19 日**，一期 **30 或 31 天**（9/20–10/19 正好 30 天）。
月份可以无限前后翻，`getPeriod()` 现算，不预生成区间。

### 3.5 覆盖层

静态班序只是底稿。改班与加班以 **(memberId, date)** 为键存成同一条覆盖记录，读取时叠回底稿：

```
有效班次 = 覆盖记录?.shift ?? 班序推算值
加班小时 = 覆盖记录?.overtimeHours ?? 0
```

四个关键行为：

- **删除记录的条件是三元判断**：`班次 == 模板 && 无加班 && 无法定`。
  ⚠️ 只看「班次是否等于模板」是错的 —— 「模板本来就是白班、今天加了 2h」会被当成没改而整条删掉，加班凭空消失。
- **「恢复默认」= 删掉整条记录**：班次回模板，**加班与法定一起清空**
- **键是 memberId 不是姓名**，所以改名不会丢历史
- **删除成员会连带删除其全部记录**，删前提示条数

这些规范化逻辑统一在 `src/data/roster.ts` 与 `src/data/overtime.ts`，界面层不要自己拼 key。

## 4. 界面结构

外壳是 L 形：左侧 228px 侧栏与 48px 顶栏共用一块 tinted 底，右下方嵌一块白色画布
（inset 8px / 圆角 16 / 1px 边 / 无阴影）。

| 区域 | 尺寸 | 内容 |
|---|---|---|
| 侧栏 | 228px | 品牌「倒班表 · 本地版」／**排班**／统计（禁用，标「下一版」）／**设置**，底部一行「N 位成员 · 数据只存在这台电脑」 |
| 顶栏 | 48px | `‹` 月份标题 `›`「回到本期」，右侧：存储状态 · 导出备份 · 导入备份 |
| 画布头部 | — | 「排班」标题 + 副标题「9/20–10/19 · 30 天 · 3 位成员」+ 视图切换 |
| 概览条 | 4 格 | 今日白班 / 今日夜班 / 今日休息 / 今日出勤（含白特夜特） |
| 主体 | 剩余高度 | 全员矩阵 **或** 个人日历（二选一） |

- **概览条**只数人不算工时。今天不在本期范围内时显示 `—` 并注明原因。
- **全员矩阵**：一行一人、一列一天，今天那列加深；改过的格子右上角有小点，
  下方固定显示六色图例。
- **个人日历**：7 列 × 5–6 行，格内显示班次 + 农历/节日角标。右上角下拉切换看谁。
  有加班的日子在班次块里补 `+3h`（同色系、小一号，不另起一行）；法定日在右上角挂一个「法」角标。
- **两个改班弹层**：
  - **矩阵弹层**：只有 6 个班次色块 + 「恢复默认 / 取消 / 保存」，**不能记加班**。
    若这天已有加班，而新选的班次不支持加班（休息/事假），会显示一行黄提示告知将一并清除。
  - **日历弹层**：班次 → 加班（预设 chips + 数字输入，0.5 步长）→ 法定（否/是）三段。
    选到休息/事假时后两段整体置灰并清零。`Esc`、点遮罩、点取消都能关。
- **设置页「班序」**：13 条内置平铺成 4 列的色条卡片（点开看 24 格，只读）；
  下面是自建班序列表（名称 + 24 格色条 + 用了几个人的 + 查看/编辑/删除），底部「新建班序」。
  自建行点「查看」会在**它自己那行下面**就地展开一张独立的 24 格卡片，按钮变「收起」。
- **24 格编辑器**：两行各 12 格，点格子选中 → 点下方**白班 / 夜班 / 休息**填入 → 自动跳下一格。
  班序里只放这三种基础班次 —— 白特、夜特、事假是临时或人为安排，改班时单天设置，不写进循环。
- **设置页「成员」**：一行一人（拖动把手 + 姓名 + 班序 + ↑ ↓ + 删除）。
  **表里的顺序就是全员矩阵的行顺序** —— 拖动行首把手可一次到位，↑ ↓ 给键盘与微调用，
  保存后矩阵同步；顺序只是 `members` 数组次序，没有额外的排序字段。
- **首开向导**：仅在成员为 0 时出现，三步——认识工具 → 填姓名挂班序 → 确认进入。

矩阵与日历**不能并排**：340（日历）+ 148（姓名列）+ 30×24（天列）+ 228（侧栏）+ 48 ≈ 1484px，
超过 1440 基准屏宽，并排必然把列压到 20px 以下，而那样「特」字放不下。所以做成视图切换。

## 5. 数据与存储

### 5.1 本机存储

| 键 | 用途 |
|---|---|
| `shift-schedule:local:roster:v2` | **唯一写入点**：整套 `{ members, overrides, patterns, updatedAt }` |

键名里的 `v2` 是历史遗留（当时从「按姓名索引的日记录」换成「按 memberId 的整套花名册」），
**与备份文件的 `version` 不是同一套编号**，别按它推断备份格式版本。

localStorage 不可用时（隐私模式、`file://` 的某些配置）自动退化为内存存储，
页面仍能跑但刷新即丢，顶栏显示「不能写入本机存储」并催你导出备份。

### 5.2 备份格式 v3

```json
{
  "app": "shift-schedule-local",
  "version": 3,
  "exportedAt": "2026-10-27T15:00:00.000Z",
  "roster": {
    "members": [{ "id": "m1", "name": "王磊", "patternId": "cp-abc123" }],
    "overrides": [
      { "memberId": "m1", "date": "2026-10-24", "shift": "休息" },
      { "memberId": "m1", "date": "2026-10-25", "shift": "白班", "overtimeHours": 3, "isLegal": true }
    ],
    "patterns": [{ "id": "cp-abc123", "name": "甲班", "shifts": ["夜班", "…共 24 项"] }]
  }
}
```

- **`patterns` 必须带**：自建班序不进备份，换台电脑恢复时成员的 `patternId` 就指向空气
- `overtimeHours` / `isLegal` 是**可选字段**，所以加班功能没有升版本号
- **不兼容旧格式**（开发阶段的明确决定）：见到顶层数组或 `dayRecords` 这类老结构，
  一律报「这是旧版本的备份文件」，不猜、不迁移。升级结构时直接改 `version` 即可，
  不需要为旧文件写适配层 —— 现在没有真实用户，也就没有值得保留的数据。
  ⚠️ 这条只对**将来**的升级生效；升级前导出的文件在同一大版本内仍可读。

### 5.3 数据不互通（容易踩）

localStorage 按「协议 + 域名 + 端口」分区，因此下面三处是**三个独立的数据空间**：

- `file://` 双击 index.html
- `http://127.0.0.1:6180/`（dev server）
- `http://localhost:6180/`

换一种方式打开看不到数据是正常的，用导出/导入备份搬运。

## 7. 视觉体系

方向是 **framed-sheet**：tinted 的 L 形外框 + 白色画布，靠一个色调台阶和 1px 边分层，
**不用阴影**。全套令牌在 `src/styles/tokens.scss`。

| 项 | 值 |
|---|---|
| 底色 / 画布 / 抬起 | `#f9fbfc` / `#ffffff` / `#f4f6f8` |
| 主文字 / 次要 / 最弱 | `#131416` / `#5d5f60` / `#8a9299` |
| 强调色 | `#1b6c80`（青，只用于当前项与链接） |
| 圆角 | 画布 16 / 卡片 8 / 控件 6 |
| 侧栏 / 顶栏 | 228px / 48px |

班次六色（背景 / 文字）：

| 班次 | 背景 | 文字 |
|---|---|---|
| 白班 `.t-day` | `#dff3ff` | `#02689f` |
| 夜班 `.t-night` | `#e3eaf3` | `#1e3a5f` |
| 休息 `.t-rest` | `#dcfce7` | `#047857` |
| 白特 `.t-dayx` | `#fff0c2` | `#b45309` |
| 夜特 `.t-nightx` | `#fde7c7` | `#9a3412` |
| 事假 `.t-leave` | `#e5e7eb` | `#475467` |

**浅色是硬约束，不是偏好**：根节点固定 `color-scheme: light`，全站**不写**
`@media (prefers-color-scheme: dark)`。否则办公机开着系统暗色模式时，
滚动条、输入框、下拉面板会被系统染黑，比「选了深色皮」更难看。

字体用系统栈，**不加载任何网络字体**——一旦引入 `@font-face`，`file://` 离线可用性立刻崩掉。

## 8. 构建产物与分发

```bash
pnpm --filter shift-schedule-local build     # → dist/
```

```
dist/
├── index.html                 入口
├── assets/app-[hash].js       全部逻辑（IIFE 单文件）
├── assets/style-[hash].css    全部样式
├── icons/                     PWA 图标
├── manifest.webmanifest       PWA 清单
├── service-worker.js          离线兜底（构建时注入指纹）
└── 使用说明.txt               给最终用户看的说明
```

产物同时满足**静态托管**和**双击 `file://` 打开**，靠 `vite.config.ts` 里四件事：

1. `base: './'` + 全相对路径 —— 放任意目录、任意子路径都不会 404
2. `format: 'iife'` + `inlineDynamicImports` —— 产出普通脚本，避开 `file://` 下 ES module 被 CORS 拦
3. `assetsInlineLimit` 拉满 —— JS/CSS 引用的资源内联成 data URI
4. 构建后把 `<script type="module" crossorigin>` 改写成 `<script defer>`，并删掉 `modulepreload`

另外 service-worker 的缓存名原本写死 `v1`，导致「清理旧缓存」的逻辑永远不触发、
旧 hash 资源无限堆积；现在构建时注入 `Date.now()` 指纹，一改版旧缓存整体清掉。

桌面版（Tauri）在 `desktop/`，前端产物目录 `dist-tauri/`：

```bash
pnpm --filter shift-schedule-local desktop:dev     # 自带 6182 的 dev server + 壳窗口
pnpm --filter shift-schedule-local desktop:build   # NSIS 安装包（需代理）
```

`desktop:dev` **不需要**先起 6180，它自己起 6182；两条线可以同时开着对比。
数据在两侧不互通（浏览器 localStorage vs 壳内 WebView2 用户目录）。
窗口主题、最小尺寸、备份在壳内的待办等细节见 [`desktop/README.md`](./desktop/README.md)。

## 10. 与 `apps/web`、`packages/core` 的关系

**没有任何依赖关系，连代码副本都不再共享。**

v1 时代这里曾拷贝一份 `packages/core` 到 `src/core/`，用 `@local/core` 别名引用。
2026-10 通用化重写时**连同别名一起删除**：本项目的模型是「班序固定 + 成员自定义」，
与 Web 版「13 个人写死在数据里」已经不是同一套逻辑，继续共享只会互相牵制。

因此：

- 不受 `apps/web` / `packages/core` 的改动影响，也不会把自己的改动回灌过去
- `package.json` 里没有任何 `workspace:*` 依赖，可单独拷出去开发
- 根目录 `DESIGN.md`（Web 与小程序的设计规范）**不适用于本项目**，视觉以
  `src/styles/tokens.scss` 为准

## 11. 已知限制

- **只做大屏 PC**：没有 `@media` 断点，窗口窄了不会崩但会拥挤；手机端不在范围内。
- **有加班数据，但没有统计**：加班小时与法定标记已经在录、也进了备份，
  但**还没有任何汇总视图**，也**不算加班费**（倍率 ×1.5 / ×2 / ×3 与薪资都留给统计页）。
- **事假不分半天**：只记班次，不记请假小时数 —— 那是统计/薪资才需要的东西。
- **周期长度不可改**：所有班序（内置与自建）都是 24 天一轮、共用锚点；
  要引入 21 天三班两倒这类循环，得改 `PATTERN_CYCLE_LENGTH` 与锚点，属于代码改动。
- **班次种类不可增删**：白/夜/休/白特/夜特/事假 六种固定，配色与单字都绑在这六种上。
- **`DESIGN-standalone.md` 已过期**：它描述的是 v1 的值班牌 + 统计页 + 与 Web 共用视觉，
  与当前实现不符。看视觉请直接读 `src/styles/tokens.scss` 或本文 §7。

## 12. 常见问题

**端口 6180 打不开 / 打开的像是另一个页面**
多半是旧 dev server 还占着端口。关掉那个窗口，或用 `dev.bat --port 7000`。

**改了代码界面没动**
vite 的 HMR 对 `src/` 与 `public/` 生效；`dist/`、`screenshots/`、`*.zip` 已被 watch 忽略
（否则跑 build 或截图会把页面刷爆）。还在看旧内容就硬刷新一次。

**数据没了**
先确认是不是换了打开方式（§5.3 的协议/域名分区），再确认有没有清浏览器缓存。
这正是「导出备份」存在的理由。
