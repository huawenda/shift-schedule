# JIG 数据查询

按 Jig ID 查 MES 导出的 Excel，并按 P/N · CST · 工序透视汇总、核对型号与尺寸是否匹配。

这一页是**桌面版专属**（静态版进不来）：它要读本地的 Excel 文件、要读系统剪贴板，
这两件事浏览器都做不了。

---

## 一、日常用法

### 1. 载入源文件

顶栏「浏览…」挑一个 MES 导出的 Excel（`.xlsx` / `.xls`）。**只读不修改源文件。**

源文件通常在车间共享盘或 D 盘。挑过一次之后目录会被记住（设置 → JIG 设置 →
源文件目录），下次直接落在那里。

### 2. 按 Jig ID 查

左栏「输入 Jig ID」每行一个 ID，粘贴进来，点「开始查询」（或 `Ctrl+Enter`）。

**可以直接从邮件正文粘贴。** 收到一封列出十几个 Jig ID 的邮件，全选复制粘进输入框，
程序会自动挑出那些 ID、把邮件正文丢掉，只留 ID 行。

> 这个功能靠读**系统剪贴板**（不是网页的剪贴板 API —— 浏览器在粘贴事件里
> 基本读不到系统剪贴板）。关掉它见设置 → JIG 设置 →「粘贴时自动提取 ID」。

### 3. 四个视图

| 页签 | 看什么 |
|---|---|
| **查询结果** | 命中的每一行明细；尺寸对不上的行标红 |
| **结果透视** | 本次命中记录按 P/N · CST · 工序的汇总 |
| **全量透视** | 全部源数据按 P/N · CST · 工序的汇总 |
| **数据审查** | 全部数据里尺寸对不上的那些行，可按 P/N 收窄 |

两张透视表里**点计数格可以下钻** —— 看到构成那个数字的具体记录，
面包屑会显示当前在哪一层（`← 返回` 或 `Esc` 退出）。

全量透视页顶部那条**工序轨道**是 11 道工序的分布 —— 一眼能看出「今天还没有 JIG
走到搬出」这类现场状态。

### 4. 导出

顶栏「导出」把**当前看到的内容**写成 xlsx：

- 在下钻里 → 导出的是明细，文件名带路径（如 `透视明细_PN-A`）
- 在审查页且切到「尺寸不匹配」→ 导出的是一张纯异常清单
- 尺寸不匹配的「对应尺寸」单元格在文件里是**红字**

## 二、型号尺寸匹配

「对应尺寸」这一列是按**型号 → 尺寸**的映射表算出来的：源文件里的「Jig 对应型号」
（如 `184`）去查表，得到该型号对应的尺寸串（如 `65/55`）。

顶栏「型号尺寸匹配」打开维护面板：

- 增删改映射行
- 拖手柄或用上下移按钮调整顺序
- 型号重复会被拦下，不让保存

**改完立刻生效** —— 查询结果、两张透视表、数据审查、导出文件，全都按新规则重算，
不用重新载入源文件。

### 尺寸的写法

尺寸串是「宽/高」，多个规格用 `_` 分隔：

```
77/48          → 宽 77 高 48
65/55_77/48    → 宽 65 高 55，或宽 77 高 48（任一匹配即算匹配）
```

**每组去掉所有非数字字符后必须恰好 4 位**才成为一个可匹配的规格码。
所以写 `77/48`（→ `7748`），不要写 `7748/7748`（→ 8 位，整组会被丢弃）。

## 三、设置

顶栏齿轮图标打开 JIG 设置。**这些只对这台电脑生效，不进备份文件** —— 换个机器
就该按新机器的情况重设（把旧机器的目录搬过去只会指向一个不存在的目录）。

| 项 | 说明 |
|---|---|
| 源文件目录 | 「浏览…」的默认位置 |
| 导出目录 | 「导出」的默认位置 |
| 表格行高 | 一行的像素高度（24 / 28 / 32） |
| 粘贴时自动提取 ID | 关掉则粘贴一律按原文 |
| 导出文件名加时间戳 | 关：`审查数据.xlsx`；开：`审查数据_20261109-1530.xlsx` |

桌面版会把**业务配置 + 本机偏好**一起写进
`%APPDATA%\com.huawenda.shiftschedule\jig-config.json`：

```jsonc
{
  "version": 1,
  "config": { ... },   // 型号→尺寸映射、工序顺序、列序…
  "prefs":  { ... }    // 目录、表格行高、粘贴开关、时间戳开关
}
```

- **文件为准**：启动时优先读它；文件不存在 / 损坏 / 版本不符才落回 localStorage 与默认值
- Web 静态版没有文件能力，仍然只用 localStorage
- 备份文件里的 `jig` 段照旧保留；导入备份会覆盖配置文件里的业务配置

## 四、备份里带了什么

备份文件（设置 → 个人资料 → 备份）现在多一段 `jig`：

```jsonc
{
  "app": "shift-schedule-local",
  "version": 6,
  "roster": { ... },        // 排班数据，不变
  "jig": { ... }           // JIG 业务配置：型号→尺寸映射、工序顺序
}
```

- **`jig` 段可选**：排班用户可能根本不装 JIG 数据，导出时不会硬塞一段默认
  配置进去。导入时缺失也不报错 —— 保持现有配置不变。
- **只放业务配置，不放本机偏好**：目录、行高、开关不跟着备份走。
- 导入备份会覆盖本机的 JIG 配置。

**备份格式版本从 v5 升到了 v6。** 按本项目一贯的做法（开发期不做旧格式兼容），
v5 的备份文件会直接报错，让你用当前版本重新导出。

## 五、界面上的几处约定

- **表格整页不滚，滚的是表格。** 表格有几百行，若让整页滚，工序轨道与工具条
  会跟着走，看不到当前范围。
- **总计行冻结在表格底部**，横向扫读时一直看得到全表合计。
- **末列「总计」独立成栏**，左侧有竖线，与明细区分开。
- **P/N 列固定在左侧**，横向滚动时它是「这一行是谁」的唯一线索。
- **左栏输入区高度独立**，不与表格联动。

## 六、常见问题

**「选择文件需要桌面版」**
静态版 / 浏览器里没有文件选择能力，这一页只在桌面壳里可用。

**选了文件但表是空的**
先确认源文件里有「Jig ID」列 —— 没有的话会提示「源文件中未找到 Jig ID 列」。

**导出的文件里没有红字**
红字只写在查询结果页、数据审查页、下钻明细这三处。透视表里是计数，
没有「对应尺寸」列可标。

**改了映射但界面没变**
不应该发生 —— 四张表都是从源数据派生的，改映射会自动重算。
若真没变，请反馈（可能是某个型号的写法有问题）。
