## 1. 背景与目标

### 1.1 现状（为什么必须重来）

| 位置 | 写死的内容 |
| --- | --- |
| `src/core/data/schedule.ts` | 13 个姓名、班组 4A–4X、24 天循环、锚点 `2026-06-07`、区间 `2026-04-19 ~ 2026-12-19` |

| `services/backup.ts` | 备份只有日覆盖记录，没有「有哪些人」这件事 |

这五处互相咬合，单点改造会做出半成品，所以整层重做。

### 1.2 目标

- 分发即用：别人拿到静态包或 exe，**3 步向导**就能建好自己的排班表。
- 规律不动：4A–4X 的 24 天循环直接照搬，用户没有编辑入口。
- 人员自由：名字、人数、谁挂哪条班序，用户说了算；同一班序可以挂多人。
- 界面是「工具」而不是「某个人的表」：带 dashboard 外壳，为后续统计页留位。

### 1.3 非目标（第一版明确不做）

统计页 · 薪资计算 · 加班小时 · 法定标记 · 事假半天/一天 · 多套排班表 · 移动端适配 · 云同步 · 账号与权限 · 节假日/农历标注（保留但不强调）。

### 1.4 成功判据

> 一个没看过这个项目的人，在不看说明的情况下，5 分钟内建好自己的排班表，并成功改一次班。

## 2. 核心模型

### 2.1 班序模板 Pattern —— 固定，不可编辑

- 内置 **20 条**模板，ID 沿用 `4A` … `4X`。
- 每条 = 24 天班次数组（`白班/夜班/休息/白特/夜特/事假`）+ 全局锚点 `2026-06-07`。
- **不可增删、不可改周期长度、不可改序列**。没有编辑入口，只在向导和设置里被"选择"。
- 模板本身不含任何姓名。

### 2.2 成员 Member

```ts
interface Member {
  id: string        // 稳定 ID（nanoid 或时间戳+随机）
  name: string      // 用户自定义姓名，表内唯一
  patternId: string // 4F…4X
  label?: string    // 可选：对该班序的本地叫法，如"甲组"（见 §9 第 3 条）
}
```

- **人数不限**（1–N）。
- **同一 `patternId` 可挂多人**，这些人每天的班次完全一致。
- `name` 表内唯一 —— 否则覆盖记录会串人，向导与设置都要拦。
- **`id` 不可变**：改名、换班序都不换 id，保证历史覆盖记录不丢。

### 2.3 结算月

- 周期固定「上月 20 日 ~ 本月 19 日」，**不提供配置**（与现有使用习惯一致）。
- 月份可无限前后翻（`2025-05` … `2030-12` 都能到）。
- **不再预生成 244 天**：改成按需推算——给定月份，现算这一期里每人每天的班次（一期 30 或 31 天，取决于月份）。这是本次唯一必要的算法改动。

### 2.4 覆盖记录 Override

```ts
interface DayOverride {
  memberId: string  // 不是姓名
  date: string      // '2026-10-24'
  shift: ShiftType  // 只存"与模板不同"的那一天
}
```

- 只存与模板不一致的日子；**恢复默认 = 删除该条**，不写空值。
- 第一版只有班次一种覆盖（无加班、无法定、无事假时长）。
- 用 `memberId` 做键：改名不丢记录；删成员时一并清理其覆盖记录。

## 3. 信息架构（PC 专用）

运行环境确定为**公司办公 PC 大屏**，因此：

- 不做移动端布局，不做触摸优化。
- 设计基准 `1440×900`；**最低可用宽度 1280**；1366×768 的机器必须不塌（矩阵内部横向滚动兜底）。
- 不做响应式断点降级，只保证不溢出。

### 3.1 外壳

```
┌───────────────┬────────────────────────────────────────────────┐
│ 倒班表  (字标) │  2026 年 10 月  ◀  ▶   今天   导出   ⚙ 设置     │ 48px 顶栏
├───────────────┼────────────────────────────────────────────────┤
│ 排班           │  ┌──────────────────────────────────────────┐  │
│ 统计  (置灰)   │  │ 今日白班 4 人 │ 夜班 5 人 │ 休息 4 人 │ 出勤 9 人 │ 概览条
│               │  └──────────────────────────────────────────┘  │
│               │  ┌──────────────────────────────────────────┐  │
│               │  │  全员矩阵 / 个人日历（右上角切换）          │  │
│  ⚙ 设置        │  └──────────────────────────────────────────┘  │
│  v1.0         │                                                │
└───────────────┴────────────────────────────────────────────────┘
   228px 侧栏            白色画布（inset 8px）
```

- 侧栏与顶栏共用一块 tinted 底（`#f9fbfc`），**两者之间没有分隔线**，形成 L 形。
- 页面是白色画布，距窗口右、下各缩进 8px，圆角 16，1px 边，**无阴影**。
- 侧栏导航：`排班`（当前，2px 墨色下划线）/ `统计`（置灰不可点，tooltip「下一版」）/ 底部 `设置` + 版本号。

### 3.2 概览条（dashboard 感的来源）

一个容器，用 1px 分隔线切成 4 格：

| 格 | 内容 |
| --- | --- |
| 今日白班 | `4` 人（14px 标签 + 24px 数字） |
| 今日夜班 | `5` 人 |
| 今日休息 | `4` 人 |
| 今日出勤 | `9` 人（白 + 夜 + 特） |

- 全部按**当前查看的月份视图里的"今天"**统计；今天不在该月范围内时，整条显示灰色 `—` 并注明「今天不在本期」。
- 只数人，不算工时、不算钱。

### 3.3 画布主区（v1.0 修订）

> **实现时改了方案。** 原计划「左侧 340px 日历 + 右侧矩阵」并排，但算宽不够：
> 340 + 姓名列 148 + 30 列 × 24 + 侧栏 228 + 内边距 48 ≈ **1484px > 1440**。
> 压到 20px 列宽又会让「白特 / 夜特」放不下，只能牺牲可读性。
> 改为**同一位置切换两种视图**，各自占满画布宽度：
>
> | 视图 | 布局 | 用途 |
> | --- | --- | --- |
> | 全员矩阵（默认） | 姓名列 148px + 30/31 天列，列宽 `minmax(22px, 1fr)` | 看全组、点格子改班 |
> | 个人日历 | 7 列 × 5–6 行，格内含班次块 + 农历/节日角标 | 看某一个人的整月 |

- 1440 宽下矩阵列宽约 33px，1280 宽约 28px，都不需要横向滚动；再窄才交给矩阵内部横滚。
- 今天列用 1.5px `--accent` 内框，并追加在列头下方 2px 强调线。**格子里只放班次单字，不加任何标记**
  （2026-10-28 按用户要求去掉「改过的日子右上角小圆点」：矩阵是扫一眼看谁上什么班，多余的点会被误读）。
- 点矩阵任意格子 = 改那个人的那天；点日历格子 = 改当前选中成员的那天。
- 视图切换是分段控件（`全员矩阵` / `个人日历`），选择记在 state 里，刷新回到默认的矩阵。

## 4. 页面与流程

### 4.1 首次打开：3 步向导

| 步 | 内容 | 校验 |
| --- | --- | --- |
| 1 | 四条说明（班序固定 / 人员自由 / 随时改班 / 数据在本机）+ 「下一步」 | — |
| 2 | 成员表：每行 `姓名` + `班序` 下拉（4F…4X）+ `别名` + 删除；「添加成员」 | 姓名非空、表内不重名、至少 1 人 |
| 3 | 确认：列出「姓名 · 班序」+ 「进入排班表」 | — |

- 第 2 步预填 3 行空行，降低"从零开始的恐惧"。
- 向导可跳过 → 落到排班页并显示空状态（「还没有成员，去设置里添加」+ 一个按钮）。
- 向导只在成员数为 0 时出现。

### 4.2 排班页操作

| 操作 | 行为 |
| --- | --- |
| 切月 | 顶栏 ◀ ▶；「回到本期」按钮跳回当前结算月 |
| 切换查看对象 | 点矩阵里的姓名，或在日历视图顶部的下拉里选 |
| 改班 | 点格子 → 弹层选 6 个班次之一 → 保存；或「恢复默认」 |
| 关闭弹层 | `Esc` / 点遮罩 / 点关闭 |

- 改班弹层：居中 420px 白面板，班次用 6 个色块选项（文字 + 色），当前值带 2px 墨框；底部「恢复默认 / 取消 / 保存」。
- 保存后文案回到顶栏状态区（`已保存：白特`），不再做格子闪烁。

### 4.3 设置页

分左右两栏（左标签列 450px + 右面板 700px），三节：

1. **成员**：表格（姓名可改 / 班序可换 / 删除）。删除时提示「将同时删除该成员 N 天的改班记录」，需二次确认。
2. **备份**：导出 JSON / 导入 JSON（覆盖前确认）。
3. **危险区**：清空全部数据（输入"清空"才可点）。

## 5. 视觉规范（framed-sheet · seed 1324561339）

### 5.0 视觉基调：默认浅色（不再是硬约束）

运行环境是**公司办公 PC**，显示器色彩与对比表现有限，所以**默认**仍是浅色纸面；
但配色按对比、可读与观感择优，不再禁止深色：

- **本版只做浅色主题**，不做暗色主题、也不做"跟随系统"；完整暗色主题留待后续。
- 根节点仍声明 `color-scheme: light`，避免系统处于暗色模式时把原生控件
  （滚动条、输入框、下拉面板）染黑。
- 深色只用于**外壳**（侧栏 + 顶栏 `#0e2228`）与**夜班反相块**（`#1e3a5f` 底 + 近白字），
  画布仍是白色。
- 画布纯白 `#ffffff` + 墨色文字 `#131416`，正文对比度全部 ≥ 4.5:1；
  控件描边 `#8f969b`（3:1）。

### 5.1 令牌

不在本文抄第二份。颜色、字号、圆角、间距令牌的唯一来源是 `src/styles/tokens.scss`；
本文只记录口径与取舍，数值冲突时一律以那份文件为准。

### 5.2 字体（离线约束下的取舍）

抽签给的是 IBM Plex Sans + Plex Mono，但**本地版必须 `file://` 离线可用、不加载网络字体**。
决策：**用系统 UI 栈**，保留抽签的字号/字重层级。

```css
font-family: "Segoe UI", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
```

- 字重：400 / 500 / 600，KPI 数字用 400、标签用 500。
- 所有会变的数字加 `font-variant-numeric: tabular-nums`。
- 数字列右对齐；矩阵列头日期居中。

### 5.3 班次色（6 种，写死）

| 班次 | 底色 | 文字 | 说明 |
| --- | --- | --- | --- |
| 白班 | `#dff3ff` | `#02689f` | 保留原色 |
| 夜班 | `#e3eaf3` | `#1e3a5f` | **已定**：去掉原来的紫 `#eee9ff`，改深蓝墨 |
| 休息 | `#dcfce7` | `#047857` | 保留原色 |
| 白特 | `#fff0c2` | `#b45309` | 保留原色 |
| 夜特 | `#fde7c7` | `#9a3412` | 保留原色 |
| 事假 | `#e5e7eb` | `#475467` | 保留原色 |

- **颜色永远配文字**，不允许靠色块单独表意。
- 概览条只统计 白/夜/休/特，事假单列在矩阵里。
- 六个色块全部在浅底上取；深色背景上一律不用这套色（本版没有深色背景）。

### 5.4 硬性禁止（会被检查）

渐变 · 光晕 · 玻璃拟态 · 带色圆底的图标 · KPI 上的迷你折线 · 彩虹图 · 卡片投影（弹层除外）· 紫色/靛色作品牌色 · 12px 以下文字 · 表格斑马纹 · **暗色主题 / 跟随系统暗色**。

### 5.5 密度

- 一个 gap 值（24px）横向纵向统一；内容内边距 24px。
- 矩阵行高 40px（含 2px 分隔线），姓名列与日期列各自显式高度，避免累积错位。
- 卡片边框不得比画布边更重。

## 13. 追加需求：自建班序（2026-10-27）

> 术语区分：**班次**＝6 种类型（白/夜/休/白特/夜特/事假，仍不可增删）；

### 13.1 已定的 8 条

| # | 决定 |

| 1 | 新增的是**班序**，不是班次类型；班次仍是 6 种 |

## 14. 追加需求：加班数录入（2026-10-28）

### 14.1 已定的四条

### 14.2 数据模型

```ts

  memberId: string
  date: string
  shift: ShiftType
  overtimeHours?: number   // 0.5 步长，0/undefined = 没有
  isLegal?: boolean
}
```

规则集中在新文件 `data/overtime.ts`（不 import core，按同一口径重写）：

- `canRecordOvertime` / `canMarkLegal`：只有 白班/夜班/白特/夜特 为真
- `getOvertimePresets`：白/夜普通 → `[2,3,3.5]`；白特/夜特或标了法定 → `[10,11,11.5]`
- `normalizeOvertimeHours`：非法/≤0 → 0，向下取到 0.5，封顶 24（与 core 一致：2.7 → 2.5）

### 14.3 最容易写错的一条（改动前必读）

原删除条件是「班次与模板相同 → 删记录」。加了加班之后这条会**静默吃掉加班**：
模板本来就是白班、今天加了 2h，此时「与模板相同」成立，整条记录被删，2 小时消失。

所以删除条件必须是三元判断：

```
班次 == 模板 && 无加班 && 无法定  →  删
否则                             →  留
```

而「恢复默认」的定义随之变成：**删掉整条记录，班次回模板，加班与法定一起清空**。

配套的联动：矩阵里把某天改成休息/事假时，已有的加班与法定**一并清掉**
（否则留下「休息 + 3h」），矩阵弹层会提前显示黄提示说明这一点。

### 14.4 备份

`overtimeHours` / `isLegal` 是**可选字段**，所以备份格式**不升版本**（仍 v3）：
旧程序读新备份只会忽略这两个字段，不会报错。

v1 旧格式的加班字段名是 **`isLegalOvertime`**（不是 `isLegal`）。既然本版开始承载加班，
v1 导入现在会把它一起带过来；缺少 `shiftOverride` 的记录用**模板班次兜底**，
所以旧版「只记了加班」的日子也能恢复。模板班次当天是休息/事假而旧记录却有加班时，
按脏数据丢弃并计入 `skippedRecords`。

### 16.1 已定的决定

| # | 决定 |
| --- | --- |
| 1 | 设置页新增「个人信息」：本人姓名 + 班序 + 四项薪资 |
| 2 | **个人日历锁定本人**，移除成员切换（含矩阵里点姓名这条隐藏入口） |

| 4 | 改本人姓名或班序＝换人：**清空本人改班记录 + 清空薪资**，确认弹层列出条数 |
| 5 | 只改薪资不清空任何东西（钱是配置，不是考勤） |
| 6 | 新增成员**不能与本人同名**（双向查：改本人名字也不能撞同事） |
| 7 | 成员表里本人那一行**只读**（带「本人」标记，删除禁用） |

| 12 | 备份升 **v4**，只认 v4 |

### 16.2 数据模型

```ts
// data/profile.ts
export interface SalaryInput { baseSalary; performanceAllowance; positionAllowance; socialFund }
export interface SelfIdentity { name: string; patternId: string }

// data/roster.ts
export interface Profile { memberId: string; salary: SalaryInput }
export interface Roster  { members; overrides; patterns; profile: Profile | null; updatedAt }

export function getSelf(roster): Member | null
export function isSelf(roster, memberId): boolean
export function selfImpact(roster, input): SelfImpact   // 清空前先算给用户看
export function validateSelf(roster, input): string[]
export function applySelf(roster, input): { roster; created; clearedOverrides }
export function saveSalary(roster, salary): Roster
```

**本人是指针不是副本**：`profile.memberId` 指向 `members` 里的一条。
存两份会让矩阵与个人信息出现两个姓名真相。金额一律 `string`（避免浮点误差、
避免输入到一半的 `1.` 被吃成 `1`）。

### 16.3 四条必须守住的行为

1. **归一化顺序**：先 `patterns` → 再 `members` → 最后校验 `profile.memberId` 是否命中。
   反了的话本人会被判成「指向不存在的人」而静默丢掉。命中不了就置 `null`
   （日历给引导），不能让整个导入失败。
2. **改本人只有一条路**：成员表本人行只读，且 `replaceMembers()` 里再兜一层——
   即使外部传进来改了姓名/班序，也强制沿用当前值。否则「改名不触发清空」这个漏洞迟早被踩到。
3. **本人所在的建班序禁止删除**：删班序是「连人带记录一起删」，会顺手删掉本人。
   `removePattern()` 返回 `blocked: 'builtin' | 'self' | null`，界面据此禁用按钮并给提示。
4. **同事的数据不能动**：`applySelf` 只过滤本人 memberId 的 overrides；

## 19. 补齐事假逻辑：时长 + 扣款（2026-10-28）

### 19.1 之前为什么是空的

第 18 章把薪资算到实发时，**事假扣款是故意留空的**：
`DayOverride` 只记「这天是事假」，不记请了半天还是一天，而薪资公式要的是**小时数**。
所以块里明写「事假未记小时，暂不扣款」——这不是忘了，是缺字段。

### 19.2 决定

| # | 决定 |
| --- | --- |
| 1 | 事假记**时长**：半天 4h / 一天 8h；不记时长按**一天** |
| 2 | 只有事假带时长，其它班次一律清掉（`sanitizeLeave`），不留「白班 + 半天」脏数据 |
| 3 | 扣款 = 时薪 × 请假小时，与 core 的 `leaveDeduction` 同口径 |
| 4 | 实发 = 应发 − 社保公积金 − 事假扣款 |
| 5 | 时长只在「半天」时写进记录；**一天是默认值，不落字段** |
| 6 | 日历格只在**半天**时挂角标（一天挂就成了每格都有的噪音） |
| 7 | 每日明细**只列加班**，事假扣款在薪资块与本月概览里体现 |

### 19.3 三条容易踩空的地方

1. **半天也算「和默认不一样」**。删除条件从「班次==模板 && 无加班 && 无法定」扩到
   `|| leave === '半天'` —— 否则「模板本就事假、今天改成半天」会被当场删掉，扣款凭空消失。
2. **矩阵弹层不能改时长，但不该抹掉它**：`applyShiftEdit` 改成事假时沿用原值，改成其它班次才丢。
3. **一天不落字段**：`normalizeOverride` 里把「一天」也收敛成 `undefined`，
   否则存量记录会同时存在「有 leaveDuration 的一天」和「没有字段的一天」两种形状。

### 19.4 界面

- **日历弹层**：选到「事假」时，在法定段之后出现「事假时长」（半天 / 一天），
  右侧提示会跟着变「按 4 小时 / 8 小时从工资里扣」。
- **日历格**：半天挂一枚中性色「半天」角标（`.cal-leave`）；一天不挂。
- **本月概览**：有事假时 foot 补一句「事假 N 天（Xh）」。
- **薪资计算**：有事假才出现「事假扣款（4h） −183.91」这一行。

## 20. 月历补齐周期外的日期（2026-10-28）

### 20.1 问题

月历是 7 列网格，但原来前导与补尾用的是**空白 div**（`.cal-cell.is-blank`）。
结果是每月首行左边、末行右边各留一块空白方块 —— 看起来像渲染失败，
而且第一行从 20 日开始、最后一行到 19 日就断，用户要靠数格子才知道那两天属于相邻的两期。

### 20.2 决定

| # | 决定 |
| --- | --- |
| 1 | 前导补**上个月**、补尾补**下个月**的真实日期，网格始终是 7 的整数倍 |
| 2 | 周期外的格子**信息与周期内完全一致**：农历、班次、加班 / 法定 / 半天事假角标都显示（最初只给日号，2026-10-28 按用户要求改正） |
| 3 | 与周期内的区别只有两处：**样式淡化**（底色 `#f1f3f5` + `opacity .72`）与**不可点**（`div` 而不是 `button`） |
| 4 | 跨月那一格不再单独标「N 月」：显示了农历与班次之后，格子本身已经能看出换月 |
| 5 | 网格计算抽成 `buildCalendarGrid(period)` 放进 `data/period.ts`，纯函数、可单测 |

### 20.3 显示班次但不计入统计 —— 这个组合是有意的

周期外的日子在**相邻两期**里确实有班次，而本月统计不含它们。看起来矛盾，但这是正确的：

- **显示**：读者需要看到「10/18 是白班」才敢确认自己没记错；
  留白会让人以为那一天真的没有排班。
- **不计入**：本期是 10/20–11/19 共 31 天，口径由结算月固定。
  把 10/18–19 算进去，所有天数、加班、薪资都错。

所以这两个决定各管一层：**格子是渲染（好看、可核对），统计是口径（只认本期）**。
两者解耦之后，「显示」不会污染「计算」，因为 `computeMonthStats` 只遍历 `period.dates`，
根本不看 `buildCalendarGrid` 的输出。

### 20.3.1 为什么周期外不可点

在 10/18 那格改班，改的其实是**上一个月那期**的记录。用户在「11 月」这个上下文里改了它，
回到「10 月」才会看到变化 —— 这种"改了看不见"的操作最容易造成数据事故。
所以周期外只渲染不接事件：想改就翻到那一期。

### 20.4 结构

```ts
// data/period.ts
export interface CalendarCell { key: string; date: string; inPeriod: boolean }
export function buildCalendarGrid(period: Period): CalendarCell[]
```

- 周期内的 `key` 直接用日期字符串；周期外用 `lead-N` / `tail-N`，避免与真实日期撞车
- `MonthCalendar` 只负责渲染：`inPeriod ? <button class="cal-cell">…</button> : <div class="cal-cell is-outside">…</div>`

3. 起始日恰好落在周日时没有前导格

## 21. 本月概览的卡片带上小时数（2026-10-28）

### 21.1 需求

原来的六张卡片只有天数（白班 13 / 夜班 11 / 休息 10 …），看不到**加班集中在哪种班上**。

| # | 决定 |
| --- | --- |
| 1 | 六张班次卡片各带**该班次的加班合计**，文案就是 `2h` / `3.5h`，**不带 `+`** |

### 21.2 数据

`MonthStats` 新增 `overtimeByShift: Record<ShiftType, number>`：

```ts
export type OvertimeByShift = Record<ShiftType, number>
```

它与三个计价桶（平日 / 特勤 / 法定）**正交**：同一笔加班既属于某个班次，也属于某个倍率桶。
两个维度各自汇总，互不影响：

- 卡片看的是「白班加了 5.5h」
- 加班分布看的是「平日 6h ×1.5」

有一条单测专门锁它们的一致性：**六个班次的加班合计必须等于 `overtime.total`**。
任何一边漏记或重复记，这条会立刻红。

### 21.3 界面

```
┌ 11  夜班                     10h ┐

┌  1  事假                     4h  ┐   ← 事假：白底 + 1px 边框的中性标记
```

- 标记用 `margin-left: auto` 靠右，不挤压天数与班次名
- 有值才渲染，0 小时不出现 —— 一排 `0h` 是噪音
- 事假标记加 `.is-leave` 换成中性底：橙色的语义是「额外付出」，用在请假小时上会误导

「知道白特多还是夜特多」，而这个月在概览层面几乎不重要；代价是六格被挤成八格，还要多扫两列。

合并只在**展示层**做：`days.daySpecial` / `days.nightSpecial` 和
`overtimeByShift.白特` / `.夜特` 都还在数据层保留着，将来想拆回去只改一个 `cards` 数组。

### 22.3 法定为什么要从班次里剥离

原来 `legal` 是**与班次正交**的一个计数：13 天白班里有 1 天法定，会同时显示「13 白班」和「1 法定」。
问题是六格相加变成 32 天，而本期只有 31 天 —— 用户会以为哪里算错了。

改成**互斥**之后：

```
31 天 = 12 白班 + 8 夜班 + 10 休息 + 0 特勤 + 0 事假 + 1 法定
```

每天只落在一格里。实现上就是 `asLegal = isLegal && isWorkShift(shift)`：
命中就进 `days.legal`，**不再进 switch**。

**加班也跟着走**（2026-10-28 定）：法定日那天记的加班，归到「法定」格，不留在白班/夜班格。
于是每一格只对应一个计价桶，能直接对账：

| 卡片 | 对应桶 |
| --- | --- |
| 白班 + 夜班 | 平日加班（×1.5） |
| 特勤 | 特勤加班（×2） |
| 法定 | 法定加班（×3） |

`MonthStats.overtimeByGroup` 因此按「格」而不是按「真实班次」汇总 ——
代价是「法定 1 天 · 10h」看不出那天原本是白班还是夜班，想看真实班次去「每日明细」。

### 22.4 三个仍然成立的约束

1. **出勤天数含法定**：`work = 白 + 夜 + 白特 + 夜特 + 法定`。法定那天确实上班，只是单独归了一格。
2. **加班按格归属**：法定日的加班进「法定」格，白班格只剩非法定日的加班。
   这样白/夜格之和恒等于平日桶、特勤格恒等于特勤桶、法定格恒等于法定桶 ——
   三条都能用单测验证（见 §22.5）。
3. **事后改判不影响历史**：把某天的法定标记取消，那天就回到原来的班次格，天数自动还原。

### 22.5 校验

`typecheck` / `test`（**179 例**，`stats.test.ts` 24 → 28）/ `build` 全绿。

新增 4 个单测：

1. 标法定的那天从白班扣 1，`legal` 加 1，`work` 不变
2. 混着标 3 天法定（白/夜/白特），六格相加仍等于本期天数
3. 法定日的加班归到「法定」格，白班格回到 0，同时仍进「法定加班」桶
4. **一格一桶**：白+夜 = 平日桶、特勤 = 特勤桶、法定 = 法定桶

`verify-dist.mjs` 新增 5 条：六格标签顺序为「白班/夜班/休息/特勤/事假/法定」、
六格相加等于 31、把某天标为法定后原班次 −1 且法定 +1、
**法定日记 3h 加班后该小时出现在「法定」格而原班次格不带小时**、清掉标记后恢复。

## 23. 每日明细：固定高度 + 内部滚动（2026-10-28）

### 23.1 问题

原来靠 `.detail-scroll { max-height: 190px }` 兜底，效果是：

- 加班记录 ≤ 3 天 → 卡片按内容自然高度，比较矮
- 记录变多 → 滚动区顶到 190px 上限，**卡片突然长高**
- 而第二行是两列 grid（薪资 / 明细），行高由较高的一侧决定 →
  **明细一长，左边的薪资卡跟着一起变高**

用户看到的就是「超过 3 项时卡片高度强行增加，还连累旁边那张」。

### 23.2 决定

| # | 决定 |
| --- | --- |
| 1 | 两张卡**永远等高**，且**高度由薪资卡决定**，明细卡自己不贡献高度 |
| 2 | 明细的表格区 `flex: 1` 吃掉剩余高度并 `overflow-y: auto`，内容在卡片内部滚 |
| 3 | 表头 `position: sticky; top: 0` **冻结**在滚动区上沿 |
| 4 | 合计行本来就在滚动区之外（`.detail-scroll` 的兄弟节点），天然冻结，保持不动 |
| 5 | 不需要任何「高度常量」：薪资项变多、窗口变窄导致换行时，两卡自动一起长高 |

### 23.2.1 为什么不用「固定 372px」

第一版写的是 `height: var(--tall-card-height)`，值从截图估算（372px）。
实测下来估大了，薪资卡底部凭空多出一截空白 —— 而这类常量只要内容或字号稍有变化就会再次失准。

改成**让明细卡不参与高度计算**：

```scss
.stat-card-detail { position: relative; padding: 0; display: block; }
.stat-card-fill   { position: absolute; inset: 0; /* flex column + padding */ }
```

外壳里没有流内内容 → 它对 grid 行高的贡献是 0 → 行高完全由薪资卡算出来 →
grid 的 `stretch` 把外壳拉成同高 → 绝对定位的内层铺满它。

好处是「等高」不再是靠两个常量对齐，而是结构上不可能不等。

### 23.3 两个实现细节

**`min-height: 0` 不能省。** flex 子项默认 `min-height: auto`，内容会把它顶开，
`overflow: auto` 就永远不会触发。定高（或跟随高度）的容器里必须显式写 `min-height: 0`。

**sticky 的表头边框会跟着滚。** `border-collapse: collapse` 的表格里，`th` 的
`border-bottom` 是画在表格边框上的，不随 sticky 走 —— 滚动时那根线会留在原地。
所以表头改用 `box-shadow: inset 0 -1px 0 var(--border)`，视觉上仍是 1px 线，但跟着表头走。

### 23.4 校验

`typecheck` / `test`（179）/ `build` 全绿。

`verify-dist.mjs` 新增 2 条：

1. 两卡高度差 ≤ 1px，且明细外壳的 `style.height` 为空（证明它没写死高度，是跟随来的）
2. `.stat-card-fill` 高度与外壳差 ≤ 2px（铺满）、`.detail-scroll` 的 `overflow-y` 是 `auto`、
   `thead th` 是 `sticky`、合计行 `closest('.detail-scroll') === null`、滚动区矮于卡片
