# 昼夜 · 个人倒班记录本（standalone）

一个**可分发**的离线排班工具：不联网、不登录、没有账号和后端，把整包拷到任何
Windows 电脑上就能用。数据只留在那台机器上 —— 浏览器打开时存在那个浏览器的
localStorage，Tauri 壳里存在 WebView2 自己的用户目录（与用户平时用的浏览器无关）；
换电脑、重装或清理这些存储之前请先导出备份。

它不绑定任何具体的人或班组。**班序是 24 天一轮的循环：20 条常用班序（4A–4X）内置只读，
不够用时可以照同样的 24 格自己再建一条；姓名、人数、谁挂哪条班序由使用者自己填。**

定位是**个人记录本**，不是「小组排班后台」：

- **本人**在设置→个人信息里填（姓名 + 班序 + 薪资基线），**个人日历只显示本人，没有切换入口**
- **同事**加进来只为了在全员矩阵里看到整组班（谁今天和你一起上夜班），他们的日历不参与、也不记加班
- 改本人姓名或班序＝换了一个人，会清空本人名下的考勤与薪资（动手前先问，并列出条数）

> 界面按 1466×900 设计（1466 是「全员矩阵」横向铺满 30 列的参考宽度）。
> 外壳已换成 shadcn `Sidebar`（展开固定 224px，可折叠成 48px 图标条）+ 顶栏 + 平铺画布：
> 桌面壳（Tauri）是无边框窗口：标题栏由前端自绘，侧栏通到窗口顶，右上是窗口按钮。
> 侧栏是一整层（标题栏段不画分隔线），右侧是左上角圆角的画布层；品牌图案与文案不变，字标放大后压到侧栏主体。
> 不再有深青 L 形外框、白色画布浮层与那层低位投影，卡片靠 1px 细边与白底分层。
> 默认浅色（根节点声明 `color-scheme: light`，避免系统暗色把原生控件染黑）；
> **暗色主题已做**：顶栏有主题切换按钮，设置 → 系统设置 → 外观 里可选
> 跟随系统 / 浅色 / 深色（默认浅色，不会跟着系统自动变）。
> 自绘标题栏与 WebView2 原生控件也跟同一套主题走：浅色白底深字、深色深底浅字，
> 切主题即时生效（链路见 `desktop/README.md`）。

## 1. 快速开始

### 双击启动（不想开终端时）

双击本目录的 **`web-dev.bat`**：起开发服务器 + 自动打开默认浏览器，关掉窗口即停止。
脚本会先 `cd` 到自己所在目录，所以从资源管理器任意位置双击都能用。

带任何参数运行时**不**自动开浏览器，方便调试：`web-dev.bat --port 7000`。

要起**桌面壳**（Tauri）则双击 **`tauri-dev.bat`**：自动起 6182 的 dev server + 编译 Rust + 开原生窗口。
它和 `web-dev.bat` 是两条独立的线，不要同时用同一个端口；两个可以并存（6180 与 6182 错开）。

### 命令行

```bash
pnpm dev                                  # http://127.0.0.1:6180/
pnpm dev -- --open                        # 顺便打开浏览器
pnpm dev -- --port 0                      # 让系统挑一个空闲端口
pnpm dev -- --lan                         # 绑 0.0.0.0，同局域网设备可访问
pnpm dev -- --strict-port                 # 端口被占用时直接报错，不自动顺延
```

端口 6180 被占（多半是上一个 dev server 没退）时，脚本会明确提示并自动顺延，
打印的地址取自实际监听结果，不会印错。

### 用现成产物（不需要 Node）

`pnpm build` 之后把 `dist/` 整个文件夹拷走，双击里面的 `index.html` 即可（见 §8）。

## 2. 这个工具做什么 / 不做什么

| 做 | 不做（本版明确不做） |
|---|---|
| 个人信息：本人姓名 / 班序 / 薪资基线（4 项） | 按天/按小时的年假、调休等其它假别 |
| 事假记时长（半天 4h / 一天 8h）并按时薪扣款 | 事假以外的假别扣款 |
| **月度概览**：个人日历 + 班次天数 / 加班分布 / 薪资计算 / 每日明细 | 全员加班分布与排名（数据源已经不存在） |
| 自定义成员（姓名、人数、挂哪条班序） | 改本人以外的成员日历 |
| 自建 24 格班序（最多 10 条，可改可删） | 改周期长度、加新班次种类 |
| 点格子改某天某人的班次，可恢复默认 | 多套排班表 / 多账套 |
| 个人日历里记加班小时、标法定节假日 | 云同步、多设备 |
| 导出/导入 JSON 备份（当前格式，不兼容旧版） | 窄屏 / 手机响应式（只做宽屏） |
| 完全离线可用（`file://` 双击即开） | — |
| **JIG DATA**（桌面版专属）：按 Jig ID 查 MES 导出的 Excel、按 P/N · CST · 工序透视、核对型号与尺寸是否匹配 | JIG 数据的在线来源（只读用户自己挑的 Excel） |
| **生产速查**：按 INCH / GLS 型号 / JIG / Recipe / FSPM 浏览与关联查询；一个输入框搜任意实体，结果列出与它有关的全部组合 | 在线更新查表数据（改表后重跑 `pnpm lookup:data`） |

统计没有单开一页：它被并进了「月度概览」，因为统计的对象就是同一份日历数据，
单开会让「看哪天加了班」和「这月加了多少」来回切页面。

「全员加班分布」和「排名」不做，不是暂缓 —— **数据源已经不存在**：
加班只在个人日历里录、而日历锁本人，同事的加班永远为空；矩阵又刻意不显示任何标记。

## 3. 核心模型

理解这四条就理解了这个项目，其余都是它们的视图。

### 3.1 本人是 members 里的一条，不另存副本

```ts
interface Profile { memberId: string; salary: SalaryInput }
interface Roster  { members; overrides; patterns; todos; profile: Profile | null; updatedAt }
```

- **本人 = `profile.memberId` 指向 `members` 里的一条**。不存第二份数据，
  否则矩阵和个人信息会有两个姓名真相，改一个另一个不同步
- `profile` 为 `null` 表示还没设置本人（跳过向导、导入了没有 profile 的备份）：
  这时日历显示「去设置里填本人信息」的引导，不退回「可切换」——那正是这次要去掉的行为
- 成员表里**本人那一行只读**（姓名/班序不可编辑、删除按钮禁用）。改本人只有一条路：
  设置 → 个人信息。`replaceMembers()` 里还兜了一层：即使外部传进来改了姓名，也强制沿用原值
- **本人所在的建班序不允许删除**（删班序是「连人带记录一起删」，会顺手删掉本人）
- 薪资 = `{ baseSalary, performanceAllowance, positionAllowance, socialFund }`，
  四个 `string`（避免浮点误差），**长期数据不按月存档**，统计任何月份都用这一组

### 3.2 班序内置 20 条，人自由

- 内置 **20 条班序**：`4A` `4C` `4D` `4E` `4F` `4G` `4H` `4I` `4J` `4K` `4M` `4O` `4Q` `4R` `4S` `4T` `4U` `4V` `4W` `4X`，**只读**
- 每条 **24 天**一个循环，锚点日 **2026-06-07**，向前向后都能推算（不需要预生成日期区间）
- 不够用时可以在设置里**自建班序**：同样 24 格，每格从固定 6 种班次里选，名字随便起，
  最多 **10 条**（`MAX_CUSTOM_PATTERNS`），**可改名、可改序列、可删除**
- **周期长度不可改**：`PATTERN_CYCLE_LENGTH` 是全局常量 24，自建班序也照此，推算算法只有一套
- 成员 = `{ id, name, patternId, groupId? }`，**同一班序可以挂多人**——这些人每天的班次完全一致
- 成员可以归到一个**分组**（`groups: { id, name }[]`，通常是部门名）：组名可改，最多 20 个；
  成员最多归一个组，`groupId` 缺省就是「未分组」。**删除分组只把人变成未分组，不删人、不删记录**
- 人数上限 200（`MAX_MEMBERS`），实际使用远到不了

改一条自建班序的 24 格会**全量生效**（包括已经过去的月份）——班序是无始无终的循环，
没有「从哪天起生效」这回事。删除自建班序会**连带删除挂在上面的成员及其改班记录**，
所以要求输入班序名字才能确认。

### 3.3 六种班次，语义写死

| 班次 | 矩阵单字 | 时段 | 算出勤 |
|---|---|---|---|
| 白班 | 白 | 08:00 起 12h | 是 |
| 夜班 | 夜 | 20:00 起 12h | 是 |
| 休息 | 休 | — | 否 |
| 白特 | 特 | 08:00 起 12h | 是 |
| 夜特 | 特 | 20:00 起 12h | 是 |
| 事假 | 假 | — | 否 |

白特/夜特在矩阵里都是「特」（22–24px 列宽放不下两个字），靠颜色和图例区分。
**颜色不单独表意**：矩阵下方永远显示六色图例，弹层里显示全称。

### 3.4 加班与法定只挂在有工时的班次上

- **能记加班的四种**：白班 / 夜班 / 白特 / 夜特。休息与事假不产生加班，选到它们时两段整体禁用并清零。
- **输入精度**：0.5 小时步长，向下取整（`2.7 → 2.5`），上限 24 小时。
- **预设档位**（Web 静态版与 Tauri 壳同一套口径）：
  - 白/夜 普通 → `2h / 3h / 3.5h`
  - 白特/夜特、或白/夜标了法定 → `10h / 11h / 11.5h`
- **加班只在「个人日历」里录**。全员矩阵的弹层保持只改班次 —— 矩阵是排班视图，
  加班是逐人逐天的明细，混在一起容易误点。
- ⚠️ 矩阵里把某天改成休息/事假时，**该天已有的加班与法定会被一并清掉**，
  弹层会提前提示「这天有 +3h 加班记录，改为休息会一并清除」。

### 3.5 结算月不是自然月

每个「月」是**上月 20 日 ~ 本月 19 日**，一期 **30 或 31 天**（9/20–10/19 正好 30 天）。
月份可以无限前后翻，`getPeriod()` 现算，不预生成区间。

### 3.6 覆盖层

静态班序只是底稿。改班与加班以 **(memberId, date)** 为键存成同一条覆盖记录，读取时叠回底稿：

```
有效班次 = 覆盖记录?.shift ?? 班序推算值
加班小时 = 覆盖记录?.overtimeHours ?? 0
```

四个关键行为：

- **删除记录的条件是三元判断**：`班次 == 模板 && 无加班 && 无法定`。
  ⚠️ 只看「班次是否等于模板」是错的 —— 「模板本来就是白班、今天加了 2h」会被当成没改而整条删掉，加班凭空消失。
- **「恢复默认」= 删掉整条记录**：班次回模板，**加班与法定一起清空**
- **键是 memberId 不是姓名**，所以改名不会丢历史
- **删除成员会连带删除其全部记录**，删前提示条数

这些规范化逻辑统一在 `src/data/roster/` 与 `src/data/overtime.ts`，界面层不要自己拼 key。

## 4. 界面结构

外壳是 shadcn `Sidebar` + 顶栏 + 平铺画布：左侧固定 224px 侧栏（可折叠成 48px 图标条），
顶栏之下直接是内容区，卡片靠 1px 细边分层、不用投影。
**本分支只做宽屏**：没有窄屏响应式，侧栏在任何窗口宽度都常驻、不收缩，也不做底部标签栏。

| 区域 | 尺寸 | 内容 |
|---|---|---|
| 侧栏 | 固定 224px（折叠 48px） | 分两组：「排班」组下是 **全员矩阵**／**月度概览**／**设置**；「业务」组下是 **JIG DATA**（桌面版专属）与 **生产速查**（Web 也显示） |
| 顶栏 | 64px | 折叠按钮 + **页面主标题**（全员矩阵 / 月度概览 / 设置 / 生产速查），右侧只有主题开关；备份的导出 / 导入收在设置页 |
| 底部提示 | — | 操作反馈统一弹在窗口底部居中，2.6–8s 后自动消失；悬停暂停，常驻提示可手动关闭 |
| 画布头部 | — | 结算月导航（`‹` 月份 `›`「回到本月」）+ 页面动作（按班次 / 按姓名、设置分页）；矩阵与概览页有这一行，速查页没有 |
| 概览条 | 3 格 | **只在全员矩阵页**：今日白班（含白特）/ 夜班（含夜特）/ 休息 |
| 值班牌 | 三列 + 节奏条 | **只在月度概览页**：现在 / 下一班 + 倒计时 / 本月六班天数 / 整期节奏条；今天日期、农历（带月份）与待办条数收在第三列 |
| 主体 | 剩余高度 | 全员矩阵 ／ 月度概览（日历 + 4 块统计） ／ **JIG DATA**（桌面版专属，四段页签 + 工序轨道） ／ **生产速查**（总览 + 四维度浏览板 + 实体关联结果） |

- **概览条**只数人不算工时：**白特并入白班、夜特并入夜班**，名单里特勤人员带「特」标记；
  每格显示人数 + 一行姓名摘要（最多三人，超出用「等」），
  点「查看名单」会弹出浮层，按成员表顺序列出完整人名与岗位（不列班序）。
  点名「查看名单」用 shadcn `Popover`（点外部或按 Esc 关闭），宽度取格子的一半
  （最小 200px，避免中文姓名逐字断行），列表超高时内部滚动；
  工作日不在本期范围内时显示 `—`；工作日按本人正在进行的班次算，夜班跨零点时 00:00–08:00 不切到新一天。
  它**只在矩阵页**：统计的是全员出勤，和矩阵同源；概览页只讲本人，不混入全员口径。
- **值班牌**只讲本人：下一班/现在 + 倒计时，后半夜仍按**正在进行的夜班**算（11/5 夜班到 11/6 08:00
  才结束，过了 00:00 仍是「距下班」而不是跳到 11/6 的班次），班次名可点（直接开对应日期的改班弹层），
  本月固定 2 行 × 3 项：白班 / 夜班 / 休息 / 白特 / 夜特 / 法定（白特、夜特各占一格，
  事假不在这里显示），**0 天也显示**，格位不随数据跳动；今天日期、农历（带月份，如「十月廿八」）与待办条数收在同一行。
- **全员矩阵**：一行一人、一列一天，今天那列加深（按工作日，夜班跨零点时停在开始那天），
  下方固定显示六色图例。视图（按班次 / 按姓名）与分组筛选的选择会记住：
  切到概览或设置再回来仍是上次的状态（刷新页面才回默认）。
  点成员列的姓名可给整行加聚焦底色，再点一次取消；只聚焦一行，点别人会换行。
  点日期表头可聚焦整列，再点取消；行聚焦与列聚焦都用加深后的底色。
  格子**只显示班次单字**，不加任何「改过 / 有加班」的标记 —— 扫一眼看谁上什么班就够了，
  多一个小点反而让人以为格子有别的含义。
- **月度概览页**（默认落地）：整页内容限宽 1180 居中 —— 双列时日历列最多 840
  （撑宽只会更空），待办吃掉剩余宽；4 块统计在日历下方按两列铺满 1180，
  宽屏多出来的空间变成左右对称的留白。单列（≤1119）时日历也铺满容器，
  与值班牌 / 待办 / 统计卡保持同一左右边界。
- **日历**：7 列 × 5–6 行，格内显示日期、农历/节日角标、班次块。**固定是本人，没有切换下拉**。
  首行前导与末行补尾用**相邻月份的真实日期**填满，**信息与周期内完全一致**
  （农历、班次、加班 / 法定 / 半天事假角标都在）；周期外只靠「底色压暗 + 整体淡一档 + 不可点」区分。
  空白的方块会让人以为渲染失败。日期网格由 `buildCalendarGrid()` 算，纯函数、有单测。
  **加班小时与「法」角标都挂在格子右上角**（并排的两枚小标签，不占班次那一行）。
  三种信息各占一处、互不重复：**班次块那圈细描边 = 这天的班次与默认（模板）不同**；
  加班看右上角橙标；法定看「法」角标。所以只记了加班、没动班次的日子，描边不出现。
  **当天有待办时，格子左下角画一个小圆点**（加班橙）—— 左下角是空的，
  不与右上角的角标挤在一起。
- **待办卡片**（日历右侧，宽约 240）：
  列出**本月全部**待办，按日期分组；每条前面一个勾选框，**在卡片里就能直接勾选完成**。
  每条待办新增时随机分配一个浅色便笺底（6 色，避开上一条），颜色随记录持久化；
  完成后保留底色，文字划线并压淡。高度与日历等高，右边界与下方统计块对齐。
  待办只给本人用（挂在 `Roster` 顶层，不带 memberId），与考勤记录**互不影响**：
  记一条待办不动班次，换本人也不清待办。
- **四块统计**（日历下方，2 × 2）：
  - **本月概览**：白班 / 夜班 / 休息 / 特勤 / 事假 / 法定 **六格天数，相加正好等于本期天数**。
    「特勤」＝白特 + 夜特（单价相同，分开只是多两格）；标了法定的那天**连它的加班**一起算「法定」，
    已从原班次里扣掉（13 天白班里 1 天法定 → 12 白班 + 1 法定）。
    每格右侧带该格的加班合计（`2h`，不带 `+`）；事假格带的是请假小时（4h / 8h，
    多天累加），用中性色而不是加班橙 —— 它是扣项，不是加项。
    这样每格只对应一个计价桶：**白+夜 = 平日、特勤 = 特勤、法定 = 法定**，能直接对账
  - **加班分布**：柱形图，常态四项（白班 / 夜班 / 白特 / 夜特）；
    有法定加班时才多出「法定」一根。纵轴是加班小时数（按最大值归一化），柱顶标数值。
    柱色与日历里的班次色块一致。标了法定的那天，加班只算进「法定」那一根，
    不重复计入它原本的班次 —— 有法定时五根相加正好等于总加班小时
  - **薪资计算**：分三组，每组标题右边跟一个该组小计 ——
    基本项（基本工资 + 绩效津贴 + 岗位津贴）、
    加班工资（平日 / 特勤 / 法定三类逐项列出 + **夜班津贴**）、
    扣款项（社保公积金 + 事假扣款，金额不带负号，靠分组和红色表示是减项）→ 应发 / 实发。
    没填基本工资时给「去个人资料填」的入口；有事假才出现「事假扣款」那一行
  - **夜班津贴**：每个夜班额外发 15 元（`夜班津贴 = 15 × 当月夜班天数`）。
    口径是**所有夜间出勤** —— 夜特、以及被标了法定的夜班都照发，
    这与「本月概览」六张卡片的互斥分类是两套口径（卡片里法定夜班归「法定」格）。
    因为不依赖时薪，没填基本工资时也算得出来
  - **每日明细**：只列**有加班**的日子（日期 / 班次 / 加班 / 当天加班费），底部合计。
    卡片高度**跟随左边的薪资卡**（自己不贡献高度）：项目多了在卡片内部滚，表头 sticky 冻结、
    合计行在滚动区之外。所以它不会再把自己撑高、连带薪资卡一起变高；
    将来薪资项增多时两卡会自动一起长高，不需要维护任何高度常量
- **两个改班弹层**：
  - **矩阵弹层**：只有 6 个班次色块 + 「恢复默认 / 取消 / 保存」，**不能记加班**。
    若这天已有加班，而新选的班次不支持加班（休息/事假），会显示一行黄提示告知将一并清除。
  - **日历弹层**：班次 → 加班（预设 chips + 数字输入，0.5 步长）→ 法定（否/是）→（仅事假时）事假时长。
    选到休息时加班与法定两段整体置灰并清零；选到事假时两段改为一张「事假不记加班与法定」的说明卡，
    并出现「半天 / 一天」时长段。待办页固定与班次页同高（318px），空态盒拉伸填满，
    列表超出时只在列表内部滚动，切换两个页签弹层高度不变。
    `Esc`、点遮罩、点取消都能关。
- **设置页分三页**（页内 tab，首次进入默认「人员配置」）：
  **人员配置** = 个人信息（本人 + 薪资，一张卡两段，排最前）+ 班序 + 成员（成员卡片内按分组 tab 切换）；
  **系统设置** = 界面 / 备份与恢复 / 危险区；**JIG DATA** = 一般（目录 / 行高 / 两个开关）+ 型号尺寸匹配，
  只在桌面壳里出现（静态版没有 JIG 的文件能力，页签本身也不渲染）。
  三段都用「组卡 + 行式设置项」（`.settings-group` / `.settings-card` / `.settings-row`）：
  左「名称 + 一句说明」、右控件靠右对齐，行间 1px 发丝线。
  分页只切渲染分支，成员表的草稿留在父组件里，所以切页不会丢未保存的改动。
  当前页签记在 hash 里，切到矩阵或概览再点「设置」仍停在上次那一页。
- **「班序」**（人员配置页）：20 条内置默认收起（点「展开」后平铺成 4 列的色条卡片，点开看 24 格，只读）；
  下面是自建班序列表（名称 + 24 格色条 + 用了几个人的 + 查看/编辑/删除），底部「新建班序」。
  自建行点「查看」会在**它自己那行下面**就地展开一张独立的 24 格卡片，按钮变「收起」。
- **24 格编辑器**：两行各 12 格，点格子选中 → 点下方**白班 / 夜班 / 休息**填入 → 自动跳下一格。
  班序里只放这三种基础班次 —— 白特、夜特、事假是临时或人为安排，改班时单天设置，不写进循环。
- **「成员」**（人员配置页）：分组与成员在同一张卡片。
  顶部是分组 tab：`全部 / 各分组 / 未分组（有人时才出现）`，右侧是「+ 新建分组」与「分组管理」；
  下方只显示当前 tab 的成员。**分组列在「全部」与「未分组」两个 tab 显示**：
  「全部」里用来把人挪到别的组，「未分组」里直接给未归组的人选一个分组，
  选完这一行立刻从「未分组」列表消失（仍需保存成员设置才落盘）；
  具体分组 tab 的归属由 tab 本身表达，不重复一列同组名。
- 添加成员落到当前 tab：在具体分组里直接进该组，在「全部 / 未分组」里先落未分组。
  成员行平时没有拖动把手，排序要先点「排序」入口，进入排序模式后拖动行首把手；
  组内顺序决定这些人在矩阵里的先后；「全部」按分组顺序排列，
  未分组最后。没建分组时「全部」就是唯一的块，可以直接排。排序模式点吸底条上的「完成」即落盘。
  本人行的姓名/班序/岗位只读，分组可在「全部」或「未分组」里改。
- 分组改名即时生效；删除分组只把组内成员变成「未分组」，成员与改班记录都保留。
- **批量导入成员**：成员表底部「从 Excel 导入」，支持 `.xlsx / .xls / .csv`。
  首行表头 `姓名 / 分组 / 班序 / 岗位`（后三列可空、列序随意），追加到现有成员末尾；
  没有表头时只按前三列「姓名 / 班序 / 岗位」读，分组列必须有表头才认；
  与现有成员（含本人）或文件内重名的跳过，班序写代号（4F）或自定义班序名都能认，
  分组按组名匹配已有分组（不分大小写），认不出来会自动新建；
  在某个分组 tab 里导入时，分组列留空的人归到当前分组；
  班序认不出来的退回默认班序并在提示里报数。**导入成功即保存并切回「全部」**。
- **首开向导**：仅在成员为 0 时出现，三步——填你自己 → 加同事（可跳过）→ 确认进入。
- **概览页的页头不再有视图切换**：入口上移到侧栏。路由是手写 hash：
  `#/overview`、`#/matrix`（当前结算月省略月份）、`#/2026-10/overview`（非当前月带月份前缀）、
  `#/settings/roster`、`#/settings/system`、`#/settings/jig`（旧的 `#/settings/profile` 归一到人员配置）；
  未知 hash 会被原地改写成规范形式。

矩阵与日历**不能并排**：340（日历）+ 148（姓名列）+ 30×24（天列）+ 224（侧栏）+ 56 ≈ 1488px，
已超过 1466 基准屏宽（还没算画布内边距），并排必然把列压到 20px 以下，而那样「特」字放不下。所以做成视图切换。

## 5. 数据与存储

### 5.1 本机存储

| 键 | 用途 |
|---|---|
| `shift-schedule:local:roster:v2` | **唯一写入点**：整套 `{ members, overrides, patterns, profile, updatedAt }` |

键名里的 `v2` 是历史遗留（当时从「按姓名索引的日记录」换成「按 memberId 的整套花名册」），
**与备份文件的 `version` 不是同一套编号**，别按它推断备份格式版本。

localStorage 不可用时（隐私模式、`file://` 的某些配置）自动退化为内存存储，
页面仍能跑但刷新即丢，底部会出一条常驻提示催你导出备份。

桌面版另有一份 JIG 配置文件：`%APPDATA%\com.huawenda.shiftschedule\jig-config.json`，
存业务配置（型号→尺寸映射、工序顺序）与本机偏好（目录、行高、开关）；**文件为准**，
localStorage 只做 Web 版回退，备份 v6 的 `jig` 段照旧、导入会覆盖文件里的业务配置。

### 5.2 备份格式 v6

```json
{
  "app": "shift-schedule-local",
  "version": 6,
  "exportedAt": "2026-10-27T15:00:00.000Z",
  "roster": {
    "members": [{ "id": "m1", "name": "王磊", "patternId": "cp-abc123", "groupId": "g-prod" }],
    "groups": [{ "id": "g-prod", "name": "生产部" }],
    "overrides": [
      { "memberId": "m1", "date": "2026-10-24", "shift": "休息" },
      { "memberId": "m1", "date": "2026-10-25", "shift": "白班", "overtimeHours": 3, "isLegal": true }
    ],
    "patterns": [{ "id": "cp-abc123", "name": "甲班", "shifts": ["夜班", "…共 24 项"] }],
    "todos": [
      { "id": "t-1", "date": "2026-10-25", "text": "交班记录表", "tone": 1, "done": false, "createdAt": 1765000000000 }
    ],
    "profile": {
      "memberId": "m1",
      "salary": { "baseSalary": "8000", "performanceAllowance": "1200", "positionAllowance": "600", "socialFund": "1500" }
    }
  },
  "jig": {
    "jigSizeMapping": { "184": "65/55", "420A": "65/55" },
    "jigSizeMappingOrder": ["184", "420A"],
    "engineeringConfig": { "PNP": { "order": 10 }, "Jig入库": { "order": 100 } }
  }
}
```

- **`jig` 段可选**：JIG 业务配置（型号→尺寸映射、工序顺序）。**排班用户可能根本不装
  JIG 数据**，导出时不会硬塞一段默认配置进去 —— 那会让「这个备份里有没有 JIG 数据」
  这件事没法判断。缺失时导入方用默认配置，不报错
- **只放业务配置，不放本机偏好**：目录、行高、开关这些是「这台电脑」的属性，
  跟着备份跑到别的机器上只会指向一个不存在的目录

- **`patterns` 必须带**：自建班序不进备份，换台电脑恢复时成员的 `patternId` 就指向空气
- **`profile` 也带上**：本人指针 + 薪资。缺失时恢复成「未设置本人」，日历会给引导；
  `memberId` 指向的成员不存在时整个 profile 归零，而不是让导入失败
- **`todos` 也带上**：待办清单。缺失时恢复成空清单，不影响其它数据
- **`groups` 也带上**：分组表。缺失时恢复成空分组表，所有人落在「未分组」；
  成员的 `groupId` 指向不存在的组时只丢分组字段，不丢人
- **版本号必须等于 6**：别的版本一律明确报「备份文件是 vN，当前版本只认 v6」。
  v5 是 JIG 段加入之前的版本，按本项目「开发期不做旧格式兼容」的既定做法直接报错
- `overtimeHours` / `isLegal` / `position` / `groupId` / `tone` 是**可选字段**，所以这些功能没有升版本号；
  旧待办没有 `tone` 时按 id 稳定散列分配便笺色，同一份备份每次导入颜色一致
- **不兼容旧格式**（开发阶段的明确决定）：见到顶层数组或 `dayRecords` 这类老结构，
  一律报「这是旧版本的备份文件」，不猜、不迁移。升级结构时直接改 `version` 即可，
  不需要为旧文件写适配层 —— 现在没有真实用户，也就没有值得保留的数据。
  ⚠️ 这条只对**将来**的升级生效；升级前导出的文件在同一大版本内仍可读。

### 5.3 数据不互通（容易踩）

localStorage 按「协议 + 域名 + 端口」分区，因此下面三处是**三个独立的数据空间**：

- `file://` 双击 index.html
- `http://127.0.0.1:6180/`（dev server）
- `http://localhost:6180/`

换一种方式打开看不到数据是正常的，用导出/导入备份搬运。

## 7. 视觉体系

方向是 **shadcn 默认**：白底 + 1px 细线分层，靠边框而不是投影区分层级。
深青只留给值班牌与矩阵概览条这两块数据元素。
项目令牌在 `src/styles/tokens.scss`，shadcn 语义变量（`--ui-*`）在 `src/index.css`。

## 8. 构建产物与分发

```bash
pnpm build     # → dist/
```

```
dist/
├── index.html                 入口
├── assets/app-[hash].js       全部逻辑（IIFE 单文件）
├── assets/style-[hash].css    全部样式
├── icons/                     PWA 图标
├── manifest.webmanifest       PWA 清单
├── service-worker.js          离线兜底（构建时注入指纹）
└── 使用说明.txt               给最终用户看的说明
```

产物同时满足**静态托管**和**双击 `file://` 打开**，靠 `vite.config.ts` 里四件事：

1. `base: './'` + 全相对路径 —— 放任意目录、任意子路径都不会 404
2. `format: 'iife'` + `inlineDynamicImports` —— 产出普通脚本，避开 `file://` 下 ES module 被 CORS 拦
3. `assetsInlineLimit` 拉满 —— JS/CSS 引用的资源内联成 data URI
4. 构建后把 `<script type="module" crossorigin>` 改写成 `<script defer>`，并删掉 `modulepreload`

另外 service-worker 的缓存名原本写死 `v1`，导致「清理旧缓存」的逻辑永远不触发、
旧 hash 资源无限堆积；现在构建时注入 `Date.now()` 指纹，一改版旧缓存整体清掉。

`使用说明.txt` 与绿色版的 `绿色版使用说明.txt` 同源：都从 `docs/使用说明模板.txt`
生成（`pnpm guides`，`pnpm build` 也会先跑一遍），只替换各自专属段落。

桌面版（Tauri）在 `desktop/`，前端产物目录 `dist-tauri/`：

```bash
pnpm desktop:dev     # 自带 6182 的 dev server + 壳窗口
pnpm desktop:build   # NSIS 安装包（需代理）
```

`desktop:dev` **不需要**先起 6180，它自己起 6182；两条线可以同时开着对比。
数据在两侧不互通（浏览器 localStorage vs 壳内 WebView2 用户目录）。

桌面壳是**单实例**：重复双击 exe 不会开第二个进程，已有窗口会从最小化或托盘隐藏状态
唤回前台（`tauri-plugin-single-instance`）。
窗口主题、最小尺寸、备份在壳内的待办等细节见 [`desktop/README.md`](./desktop/README.md)。

桌面壳常驻托盘：左键单击显示并聚焦窗口，右键菜单可「显示 / 隐藏主窗口」与「退出」。
关闭按钮默认直接退出；可在 设置 → 系统设置 → 窗口 改成「隐藏到托盘」，程序继续在后台运行。

## 11. 已知限制

- **只做宽屏**：不做窄屏 / 手机响应式，侧栏恒 224px、不随窗口收缩；窗口窄了由容器查询与各自的滚动容器消化（日历 / 待办在 1024–1119 拆单列），手机端不在范围内。
- **只有事假能记时长**：半天 4h / 一天 8h（不记时长按一天），扣款 = 时薪 × 请假小时。
  年假、调休、病假这些假种没有 —— 六种班次是固定的，加假种要动整套配色与统计口径。
- **薪资是一组固定值**：不做按月存档（一年才变一次的长期数据），统计任何月份都用这一组。
- **同事没有加班数据**：加班只在个人日历里录，而日历锁本人 —— 这是设计意图，不是缺功能。
- **周期长度不可改**：所有班序（内置与自建）都是 24 天一轮、共用锚点；
  要引入 21 天三班两倒这类循环，得改 `PATTERN_CYCLE_LENGTH` 与锚点，属于代码改动。
- **班次种类不可增删**：白/夜/休/白特/夜特/事假 六种固定，配色与单字都绑在这六种上。
- **`DESIGN.md` 已于 2026-10-30 按当前实现重写**：它讲视觉体系与「为什么这么定」，
  数值以 `src/styles/tokens.scss` 为准，本文 §7 是速查表。三者冲突时按 tokens → 本文 → DESIGN 排优先级。

## 12. 常见问题

**端口 6180 打不开 / 打开的像是另一个页面**
多半是旧 dev server 还占着端口。关掉那个窗口，或用 `web-dev.bat --port 7000`。

**改了代码界面没动**
vite 的 HMR 对 `src/` 与 `public/` 生效；`dist/`、`screenshots/`、`*.zip` 已被 watch 忽略
（否则跑 build 或截图会把页面刷爆）。还在看旧内容就硬刷新一次。

**数据没了**
先确认是不是换了打开方式（§5.3 的协议/域名分区），再确认有没有清浏览器缓存。
这正是「导出备份」存在的理由。
