可引进的 6 个通用控件

外观不变，行为升级：每张卡片默认展示手写复刻的外观示意，下方按钮用于体验模拟交互。这 6 类是 shadcn / Radix 能直接接管的通用控件范围。

手写复刻 · 非 shadcn 组件
本页不是 shadcn 组件。所有卡片、按钮、弹层、表格都是手写 HTML/CSS 的外观示意， 用 src/styles/tokens.scss 的变量值复刻；交互由原生 JS 模拟 Radix 行为。 页面没有 React、没有 Tailwind、没有 Radix，也没有 shadcn CLI 生成的组件文件，src/ 一行未改。
要看真实的 shadcn 组件，需要接入 Tailwind v4 + Radix 并调整两份 Vite 配置（根目录与 desktop/）， 那是重构动作，本页未做。这一页只能用来判断「接入后大概长什么样、交互会多出什么」。

通用外壳是什么样子

「通用外壳」= 不带业务语义的容器与骨架：卡片边框 / 圆角 / 内边距、标题行、表格的 thead / tbody、徽章、图表容器。 shadcn 提供的是这些结构、默认样式与无障碍语义，数据、算法、配色规则仍要你自己填。

统计区：为什么不整体引入

可以引入的通用部件对应 shadcn不能交给组件库的部分
四张统计卡的外壳 / 标题Card / CardHeader业务口径全部在 src/data/stats.ts：六格天数互斥求和、三类加班 ×1.5/×2/×3、夜班津贴 15 元/天、事假 4h/8h 扣款、柱图按最大值归一化
每日明细表格Table / TableCell
加班分布柱形图Chart / Progress
加班费胶囊、班次标签、空态Badge / Alert

「不整体引入」的三个真实原因：① 业务口径是纯函数，UI 库不提供、也不能代算； ② 加班分布卡与每日明细卡「高度不自己定」——内容绝对定位、由 grid stretch 拉齐到左边卡片，薪资项变多时两卡自动一起长高，表头 sticky、合计行在滚动区外，这套耦合布局 shadcn Card 没有； ③ 柱色复用 .t-day / .t-night 班次语义色与 pay-pill 三档色，属于数据色而非主题色。
所以准确结论是「通用外壳可换、业务口径与定制布局不换」，而不是「统计区完全不引入」。此前把它一刀切排除，措辞不准确。

不在替换范围：月历网格、全员矩阵（sticky 表头 / 姓名列）、24 格班序编辑器、值班牌、待办便笺等业务组件，以及 6390 行布局 SCSS 与三档断点（≤1399 / ≤1023 / ≤639）。这些高度定制的界面仍需自研。
验收约束：scripts/verify-dist.mjs 的 412 项通过 .dialog / .cal-cell / .btn-primary 等自定义 class 定位，因此组件外壳保留原类名作为契约，可把脚本改动压到最小。

本页是零侵入原型：颜色、字号、圆角、阴影全部取自 src/styles/tokens.scss，交互由原生 JS 模拟 Radix 行为，并非真实 shadcn 运行时；暗色仅为展示 .dark 收益的示意配色，项目尚未实现完整暗色主题。页面不引用任何外部资源，可离线双击打开。
